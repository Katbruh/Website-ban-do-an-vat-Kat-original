# Kat UX and rubric audit

Audit date: 2026-11-04. Sources: local HTML, CSS and JavaScript; project handoff; assignment rubric; owner-supplied screenshots of the earlier Maika storefront; and `REFERENCE-REVIEW.md`. This is a code review. The changed pages have not been visually re-rendered or exercised in a browser.

| # | Requirement or issue | Change in this build | Evidence in project |
|---|---|---|---|
| 1 | The first screen should lead into choosing and ordering food. | Home page uses a photo-led snack showcase, menu action and delivery or pickup choice. Featured snacks and combo deals follow. | `index.html`, `js/main.js` |
| 2 | Visitors need quick navigation to menu, offers, branches, feedback, cart, account and order tracking. | A sticky orange navigation centers the five page links; cart and account use compact icons. Guest checkout remains available. | `index.html`, `js/auth.js`, `cart.html`, `login.html`, `orders.html` |
| 3 | Shop name, contact and branch information must remain editable placeholders. | Kat is the store name. Branch address, opening hours, phone and email display explicit placeholders; Maika and Popeyes facts are not used as Kat data. | `index.html`, `cart.html`, `login.html`, `orders.html`, `js/initdata.js` |
| 4 | Search by product name, then combine category and price filters; show results with pagination. | Name search includes grouped choices; price filtering checks each choice price. Category and price filters combine; results paginate six cards at a time. | `menu.html`, `js/main.js`, `css/style.css` |
| 5 | Customers should browse snack items and customize options. | The sample catalog remains a snack shop. Product detail supports food or drink options, topping prices, quantity and quick add. | `js/initdata.js`, `js/main.js` |
| 6 | Customers can register, log in and still order as guests. | Registration creates a customer account. Guest checkout remains separate from sign-in. The checkout pre-fills the signed-in customer's name and phone. | `login.html`, `js/auth.js`, `js/login.js`, `cart.html` |
| 7 | Checkout must support a saved account address or a new address. | Signed-in customers with a saved address can choose it or enter a new address. Successful delivery checkout updates the account address. | `cart.html`, `js/cart.js` |
| 8 | Cart, delivery or pickup, vouchers and payment choice are required. | Cart quantity controls, branch selection, delivery fee, percentage/fixed/shipping vouchers, cash on delivery and a clearly marked QR demo remain available. The QR demo does not start a real payment. | `cart.html`, `js/cart.js`, `js/initdata.js` |
| 9 | Customers need an order confirmation and grouped purchase history. | New orders are stored with an order identifier, items, totals and timestamp. Signed-in customers see each order with its item list and a link to the order detail. Guests can look up orders by order identifier and phone. | `orders.html`, `js/cart.js`, `js/orders.js` |
| 10 | Admin and customer share one login; admin management appears after authentication. | One login accepts a phone number or username, returns to the previous allowed page, and shows “Quản lý cửa hàng” in the signed-in admin menu. There are no sample autofill controls. | `login.html`, `js/login.js`, `js/auth.js`, `admin.html` |
| 11 | Admin needs product and category management, including image upload preview and correct edit details. | Product form shows the current category and image, previews a selected image, and saves it with the chosen category. Admin can manage product visibility and availability separately. | `admin.html`, `js/admin.js` |
| 12 | Product deletion must preserve sold items and their history. | A product in a completed order is hidden from the customer catalog and retained for order history. An unsold product requires confirmation before deletion. | `js/admin.js`, `js/main.js` |
| 13 | Admin needs customer account management. | Admin can create and edit customer accounts, set a password, and block or restore access. The active admin cannot lock their own session or the last active administrator. | `admin.html`, `js/admin.js`, `js/auth.js` |
| 14 | Admin order handling must move forward and support filters. | Orders can advance through pending, preparing, shipping and completed, or be cancelled before completion. Completed and cancelled orders are locked. Admin can filter by status, date range and text found in the delivery or pickup address. | `js/admin.js`, `js/cart.js` |
| 15 | Admin analytics must show five leading customers and their grouped orders for a date range. | Overview ranks customers by completed-order total in descending order. Each row shows total and order count, with its orders grouped below and linked to order details. | `js/admin.js`, `js/cart.js`, `orders.html` |
| 16 | The instructor may open `index.html` directly in Chrome. | The homepage has a memory fallback if local storage is unavailable. For persistent data shared across pages, the documented local server remains the reliable path. | `js/initdata.js`, `README.md` |
| 17 | The previous dark appearance must be removed. | The storefront and generated design tokens use the light theme only. | `DESIGN.md`, `opendesigner/state.json`, `css/style.css` |
| 18 | The menu and offers pages should focus on browsing; subpages should share one footer. | Menu has no footer. Offers shows nine priced snack combos instead of voucher cards, with drink selection in a popup. All other pages render the same footer template. | `offers.html`, `menu.html`, `js/main.js`, `js/auth.js` |

## Limits

This audit records implementation from code, not a live browser check. The supplied screenshots show the earlier Maika storefront in dark appearance and cannot verify the renamed Kat site, light theme, mobile layouts, checkout, admin states, keyboard use or motion. The current visual review report remains incomplete. See `REPORT.md` and `SCREENSHOT-NOTES.md`.

The Popeyes homepage, offers and category pages returned 403 to the available web reader. No bot check or alternate access path was used. Maika and Popeyes are navigation references only; Kat's menu data, copy and editable store details are its own.
